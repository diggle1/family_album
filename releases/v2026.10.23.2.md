## 升级

```bash
# 先停应用。不要加 -v，否则会删掉命名卷。
docker compose stop

# 备份命名卷（卷名以 docker volume ls 为准，通常是 <项目>_app-data）
mkdir -p backup
docker run --rm \
  -v family_album_app-data:/data \
  -v "$PWD/backup":/backup \
  alpine tar czf /backup/app-data-before-2026.10.23.2.tgz -C /data .

# 拉新代码后
docker compose up -d --build
```

`up` 时会执行迁移。不使用 Docker 时：

```bash
python scripts/migrate.py
```

确认旧照片的 `storage_backend` 为 `local`，并且 `/media` 仍返回 200。S3 上的新对象不在这次 SQLite 备份里，需要按桶自己做副本。

## 回退

回退到上一版 tag `v2026.10.23.1`。代码回退不会删除卷，也不会删除桶里的对象。

```bash
docker compose stop

# 代码
git checkout v2026.10.23.1

# 数据卷还在。不要执行 docker compose down -v，除非确定要丢掉 /data。
# 若迁移后的库不能给旧代码用，用升级前的备份盖回去：
docker run --rm \
  -v family_album_app-data:/data \
  -v "$PWD/backup":/backup \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/app-data-before-2026.10.23.2.tgz -C /data'

docker compose up -d --build
```

说明：

- 命名卷 `app-data`（挂在 `/data`，含 `app.db` 和 `media/`）不随 `git checkout` 消失。`docker compose down` 默认也保留命名卷；`down -v` 会删掉。
- `ALTER` 多出来的 `storage_backend` 列，旧代码的 INSERT 不写它，SQLite 默认值是 `local`。只在本地盘上的旧照片，旧代码仍按 `storage_path` 去读文件。
- 本版新上传到 S3 的对象留在桶里。`v2026.10.23.1` 不会去读 S3，这些对象也不会被 git 回退删除。若要丢掉它们，在对象存储控制台或 CLI 里按桶删除，不要把密钥写进 shell 历史后提交。
- 若库已经不兼容，用升级前的 `app-data` 备份恢复，而不是只改代码。

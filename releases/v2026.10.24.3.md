本文件在合并并完成双 QA、终审之后由工程师打 tag。实现不在本仓库里执行 `git tag`。

相对 `v2026.10.24.2`。新增两张表，不改旧表。

## In

- 家人可以给一个孩子写成长日志：纯文字，引用 0–9 张家里已经有的照片，挂在某一天，和照片一起出现在时光线上。
- 作者可以改、删自己写的。家长可以删任何人写的，不能改别人的。只读长辈只能看。
- 日志只在本家庭内可见。没有公开链接、评论、点赞。草稿只在这台设备上，退出登录时清掉。删日志不会删照片。
- 「我的数据」ZIP 里多一个 `日志.md`，只含本人写的，永久免费。有日志、0 张本人照片时仍然出包。导出界面的文案和入口不改。

## 数据库

新增 `journals`、`journal_photos`。旧表不动。

升级前备份（路径以部署 `.env` 里的 `DATABASE_URL` 为准）：

```bash
docker compose exec web python -c "import sqlite3;s=sqlite3.connect('/data/app.db');d=sqlite3.connect('/data/app.db.bak-v2026.10.24.2');s.backup(d)"
```

## 升级

```bash
docker compose stop
docker compose up -d --build
```

容器启动时 `scripts/migrate.py` 会建出新表。重复执行不会改掉已有数据。

不使用 Docker 时拉代码后执行 `python scripts/migrate.py`，再重启进程。

## 回退

回退到 `v2026.10.24.2`。新表留在库里，旧版本不读也不写。

```bash
docker compose stop
git checkout v2026.10.24.2
docker compose up -d --build
```

不要执行 `docker compose down -v`。不要 `DROP TABLE`。那一步不可逆；若要彻底撤掉这两张表，另走数据删除审批，先备份再手动执行。

## 已知限制

- 现在没有删照片、删孩子、移出成员的入口。这些情况按约定实现并有测试，目前只会在直接改库或以后的版本里出现。
- 草稿只在这台设备的这个浏览器里。换设备看不到。隐私模式或清掉站点数据时，草稿会丢。
- 会话过期、又没点退出时，上一位用户的草稿要等下一个人打开第一页才会清。
- 有日志、0 张本人照片时仍可导出，ZIP 里可能只有 `日志.md`。界面文案仍可能说「导出照片」。
- 字数按 Unicode 码点计算。组合表情会算成多个字。
- 删掉的日志在库里留一条没有正文的记录，用来认出已经用过的幂等键。
- 同一个作者开两个窗口改同一条，后保存的覆盖先保存的，不另外提示。
- 浏览器草稿键是 `kids.journal.draft.{家庭}.{用户}…`。设计稿里少写了 `kids.` 前缀，以实现这份技术说明为准。

# v2026.10.25.1

日期：2026-10-25

本文件随实现一并放入仓库。打 tag 和发布不在这一步做。

相对 `v2026.10.24.4`。新增两张关联表，不改旧表的列。

## In

- 一条日志、一段视频可以关联本家庭的多个孩子。请求用 `child_ids`，顺序保留。主表 `child_id` 写成第一项，供旧版本读取。
- 只传原来的 `child_id` 时，当成只有一个孩子。两个字段都传时，只认 `child_ids`。
- 时光线：孩子视图按关联过滤；全家视图同一条只一张卡。叠堆列出全部关联孩子，年龄按记录当天计算。
- 写页和上传页用兄弟姐妹条。从 `?child=` 进来预选该孩子。不能把已选的最后一位取消。
- 视频可以用 `PATCH /api/videos/{id}` 改关联和日期，不能换片。
- 导出只在关联多于一个孩子时追加元数据。导出页面不改。

## 数据库

新增 `journal_children`、`video_children`。`child_id` 没有外键。旧的 `journals.child_id`、`videos.child_id` 保留。

升级前备份（路径以部署 `.env` 里的 `DATABASE_URL` 为准）：

```bash
docker compose exec web python -c "import sqlite3;s=sqlite3.connect('/data/app.db');d=sqlite3.connect('/data/app.db.bak-v2026.10.24.4');s.backup(d)"
```

## 升级

```bash
docker compose stop
docker compose up -d --build
```

容器启动时 `scripts/migrate.py` 会建出两张关联表，并把还没有关联行的旧记录按 `child_id` 补上一行。重复执行不会改掉已经存在的关联。照片、视频文件和已经打好的导出包不动。

不使用 Docker 时拉代码后执行 `python scripts/migrate.py`，再重启进程。

## 回退

回退到 `v2026.10.24.4`。两张关联表留在库里，旧版本不读也不写，仍用主表上的 `child_id`。

```bash
docker compose stop
git checkout v2026.10.24.4
docker compose up -d --build
```

不要执行 `docker compose down -v`。不要 `DROP TABLE`。那一步不可逆；若要彻底撤掉关联表，另走数据删除审批，先备份再手动执行。

## 已知限制

- 不做 0 个孩子的网盘，也不做商城、发现、广告、会员。
- 照片仍然只属于一个孩子。导出界面的文案和入口不改。
- 关联孩子多于本家庭孩子人数时拒绝。重复的 id 会收成一次，不按重复次数计数。
- 视频编辑只能改关联和日期，不能换原片。
- 旧版日志、视频常量里的「先选写给哪个孩子」「先选挂给哪个孩子」仍留在原常量里，供上一版文案测试锁定。多孩子这条路径使用「至少选一个孩子」。

## 实现说明

规格是挂载的 tech（md5 `1a80f59469fa2dd1403d002579eaa8b2`，报告用这个 md5，短前缀 `1a80f594`）。终稿 mockup md5 `2bdab7983095c7e7b81a7c7715b73211`。

- 产品文案 49 键在 `app/multi_child_copy.py`，由 `constants.MULTI_CHILD` 再导出。mockup 里的 4 个 `anno_*` 稿注不进产品常量。
- 主关联是请求数组的第一项（`child_ids[0]`），不是按 id 排序。
- 恰好一个孩子时，日志 Markdown 和视频 ZIP 文件名与 `v2026.10.24.4` 相同。多于一个孩子时，日志在「孩子：」下面加一行 `child_ids：`，视频增加 `{日期}_{id}.children.json`。
- 未选孩子：走 `child_ids` 时 `detail` 是「至少选一个孩子」。只传旧字段且缺失时，仍用日志或视频常量里的原句，避免改掉已锁定的文案表。

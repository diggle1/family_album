升级前备份（路径以部署 `.env` 里的 `DATABASE_URL` 为准）：

```bash
docker compose exec web python -c "import sqlite3;s=sqlite3.connect('/data/app.db');d=sqlite3.connect('/data/app.db.bak-v2026.10.25.1');s.backup(d)"
```

## 升级

```bash
docker compose stop
docker compose up -d --build
```

容器启动时 `scripts/migrate.py` 会在缺列时执行 `ALTER TABLE families ADD COLUMN family_access_url VARCHAR(512)`。列已经在时再跑一次，只打印 `family_access_url ready`，不改已填的地址。照片、日志、视频和已经打好的导出包不动。

不使用 Docker 时拉代码后执行 `python scripts/migrate.py`，再重启进程。

## 回退

回退到 `v2026.10.25.1`。`family_access_url` 列留在库里，旧版本不读也不写。再升回本版后，已经填过的地址还在。

```bash
docker compose stop
git checkout v2026.10.25.1
docker compose up -d --build
```

不要执行 `docker compose down -v`。不要 `DROP COLUMN`，也不要 `DROP TABLE`。那一步不可逆；若要彻底撤掉这一列，另走数据删除审批，先备份再手动执行。

- 浏览器若不允许写入剪贴板，笺上会留下可选中的正文，这时不提示「已复制」。

- 回退到 `v2026.10.25.1` 期间没有这张笺，邀请页也回到上一版的句子。地址列仍留在库里。

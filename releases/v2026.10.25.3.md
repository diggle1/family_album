## In

- 孩子照片可以贴给家里一个或多个孩子。上传页在选了「孩子照片」之后才出现胶片贴。从某个孩子的时光线进来会先贴上这个孩子，还可以再贴兄弟姐妹。最后一个不能撕掉。一个都没贴时，底下是红条，主按钮不能点。单孩家庭自动贴上这一位。
- 一张照片出现在每个被贴上的孩子时光线里。全家视图同一张只一张卡，不按孩子复制。同一天仍是日志、视频、照片这个顺序。年龄按拍摄日算，写在卡片和详情上，胶片贴条上不写年龄。
- 作者或家长管理员可以改已经贴上的孩子，不能换照片文件，也不能把孩子照改成本人照。去掉全部孩子不能保存。
- 家人本人照片仍走原来的入口：没有胶片贴，不进孩子时光线，也不写关联表。
- 「我的数据」里，关联多于一个孩子的照片多一个 `{拍摄日}_{id}.children.json`。恰好一个孩子时，压缩包里的文件名与上一版相同。导出页的句子和按钮不动。

## 数据库

新增表 `photo_children`（`photo_id`、`child_id`、`position`）。`child_id` 没有指向 `children` 的外键。`photo_id` 随照片删除。`photos.child_id` 的外键和检查约束保持原样。写入时这一列等于请求里 `child_ids` 的第一项。

升级时把已经存在的孩子照片投影成一行关联，不拆成多行。本人照片不插入。已经有关联行的照片不会被覆盖。

升级前备份（路径以部署 `.env` 里的 `DATABASE_URL` 为准）：

```bash
docker compose exec web python -c "import sqlite3;s=sqlite3.connect('/data/app.db');d=sqlite3.connect('/data/app.db.bak-v2026.10.25.2');s.backup(d)"
```

## 升级

```bash
docker compose stop
docker compose up -d --build
```

容器启动时 `scripts/migrate.py` 建 `photo_children` 并做上面的投影，然后打印 `photo_children ready`。表已经在时再跑一次，不改已经写好的多选。

不使用 Docker 时拉代码后执行 `python scripts/migrate.py`，再重启进程。

## 修复

全家时光线不再把第一个孩子交给上传入口。直接打开 `/?view=family`，或先打开某个孩子（例如豆豆）再切到全家，照片入口和视频入口都不带 `child`，不会预选。从某个孩子的时光线进去，仍预选这一个孩子。视频只改了这一处入口，关联规则和视频页不动。

上传页 `/upload?kind=child` 和编辑页 `/photos/{id}/edit` 自上而下是日期、大图、胶片贴。胶片贴在照片预览下面、文案上面。一个孩子都没选时，红条全宽，放在主按钮上方、底栏之上；主按钮置灰，不能点。照片详情的编辑是顶栏可点的 ✎，不在 ⋯ 菜单里。
